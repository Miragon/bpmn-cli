# Audit, October 2026

A broad audit of `bpmn-cli` after the incremental layout and the format
operations landed (see HANDOVER.md). Eight independent streams tried to break
the CLI from different angles; a ninth pass re-ran every reported bug and kept
only what it could reproduce. This document summarises what was tested, what
held, and the 77 confirmed bugs. It contains aggregate numbers only: the real
models used come from private sources and stay outside this repository.

How to run the same kinds of checks yourself: [testing.md](testing.md).

## Verdict

- **The semantic layer and the write pipeline are robust.** Across about
  60,000 mutations (CLI calls and in-process dry runs) there was no crash, no
  write on a failed command, and every written file re-imported cleanly.
  Vendor extensions an edit did not touch survived every write in auto and
  incremental mode (#2 is the exception: an edited event definition).
- **The CLI is deterministic and fast.** Same input, same bytes, regardless of
  working directory, time zone or locale. Models of 300 flow nodes take about
  0.2–0.3 s per edit.
- **Layout quality is where the bugs are.** The incremental engine adds a hard
  defect (overlap, flow through a shape, node outside its lane / pool /
  sub-process) in roughly 0.4–1.2 % of steps, more with nested sub-processes,
  and the metrics did not see a whole class of defects (a frame covering foreign
  shapes).
- **Integration gaps for an embedding host** (Miragon/design-iq, PR #218 tool
  `@bpmiq/bpmn-edit`): formatting churn on write, no platform awareness, the
  library is not browser-safe.

## Results

### Robustness

| invariant (scale / fuzz stream, 37,400 calls) | result |
| --- | --- |
| crash (exit 70, signal, timeout) | 0 |
| usage error on a generated op | 0 |
| file modified by a failed command | 0 of 1,660 refusals |
| new import warnings after a write | 0 |
| duplicate, dangling, stale or missing DI | 0 |
| NaN, negative or zero sizes | 0 |
| BPMNEdge with fewer than 2 waypoints | 1 (bug #10) |
| DI on the wrong plane | 18, all associations after a collapse (bug #15) |
| shapes moved without being reported | 0 |
| connections reshaped without being reported | 91 (bug #61) |
| result metrics vs a standalone `metrics` run | 0 mismatches |

The other streams agree: the complex-structure hunt found every written file
re-importable with DI on the right plane (including drill-down planes) and the
guards (cross-scope, invalid trigger, lane membership, moving a sub-process into
its own child, cancel / compensation / error-start checks) correct in every
case tried. In auto and incremental mode no run lost or changed extension
elements, vendor attributes, documentation or namespace declarations; DI losses
came from full redraws only.

### Determinism

- 10 walk pairs of 40 ops: all 370 written step files byte-identical, JSON
  results identical apart from timing.
- The same batch from another working directory, time zone and locale:
  byte-identical.
- Fixpoints: `layout(layout(x)) == layout(x)` and `tidy(tidy(x)) == tidy(x)` on
  309 of 309 files.
- A second no-op write on the CLI's own output was byte-identical for every
  real and scenario file.
- No `Math.random` or date use in `src/`.

### Performance

Measured under heavy host load (upper bounds), median of 3 runs:

| model size | incremental | full | `--no-layout` |
| --- | --- | --- | --- |
| 120–128 flow nodes | 118 ms (max 140) | 141 ms (max 173) | 103 ms |
| 300–317 flow nodes | 213 ms (max 352) | 268 ms (max 402) | 180 ms |

Node start-up is about 45 ms. The PR #218 layouter needed 14–15 s for the
300-node models. Output size, not speed, is the scaling problem for agents:
`show` on 317 nodes is about 39 KB (about 10k tokens), `show --json` about
159 KB, and a plain `add` on such a model returns about 3.7k tokens, mostly
repeated pre-existing lint warnings (bug #60).

### Layout quality

- Scale fuzzing: 225 of 35,260 successful steps (0.64 %) added a hard defect
  the metrics report, in 143 of 568 walks. A further 0.77 % of steps (one
  campaign) produced frame intrusions or overlapping frames the metrics could
  not see (bug #8).
- Worst operations by hard-defect rate: `place --below --column-of` 5.3 %,
  expand / collapse 3.7 %, lane order 3.0 %, `align` 2.5 %, `split` 1.4 %,
  add after 1.0 %, add into a flow 0.8 %. 0 % for rename, retype, color, label,
  remove flow, space after, tidy and lane moves.
- Probes (208 files, real and public): 73 of 6,011 runs (1.2 %) added a
  reported hard defect; 7 added a silent frame intrusion. Agent sessions on real models: 0.41 % of
  steps added a reported hard defect, 0.81 % a silent one, and 15 % of 30-step
  sessions ended with at least one layout defect.
- Nested sub-processes: 29 of 246 inserts (12 %) into nested sub-processes of
  real models let a growing frame cover a neighbour; the metrics reported
  "score 0 -> 0" in 34 of the 35 affected runs (bugs #4, #8).
- Full redraws: on lane models with loops the clean engine can place nodes
  outside their lanes and score far worse than `--engine auto` (bug #7); event
  sub-processes, collaboration annotations and cross-scope associations have
  dedicated full-engine bugs (#17–#20, #23, #24).
- Locality of incremental edits (share of existing shapes moved, median / p90):
  add after 9 % / 69 %, add into a flow 20 % / 76 %, split 31 % / 80 %, lane
  move 2 % / 7 %, remove 0 % / 37 %.

### Roundtrip fidelity

- No vendor content lost in any write (camunda, zeebe, modeler, bioc / color,
  unknown attributes, host stickies).
- Relative to a no-op write, a rename changes exactly 2 lines in 257 of 259
  files.
- Formatting churn: namespace declarations reordered (206 of 259 files), vendor
  attributes moved behind typed ones (57), XML comments dropped (61), CDATA
  rewritten (2), derived `incoming` / `outgoing` lists added (bugs #30, #31,
  #44, #45). A no-op write is byte-identical in only 15 % of real files; a
  text-preserving post-pass prototype raised that to 92 % and cut the median
  rename diff from 5 to 2 lines.
- 6 of 265 writable real files were refused with E_VALIDATION, 4 of them false
  positives (vendor form-field ids counted as BPMN ids, bug #1).

### Agent ergonomics (dogfooding)

- Building three models from a brief: 58 calls, 6 errors (id guesses, pool
  order, a wrong key), no XML fallback; renders were essential to see problems
  the metrics missed.
- Five large real models: navigation questions took 2–24 calls; 3 XML
  fallbacks were needed; 150–350 ms per call on a 92 KB model.

## Step 1 (2026-10-08)

The first fix round took all seven high-severity bugs and twelve medium
ones (statuses in the table above), plus problems the gate itself found:

- **Semantic layer** (#1, #2, #3, #26, #34, #35): vendor extension ids are no
  longer BPMN ids; changing trigger details keeps the event definition;
  `mutateDoc` refuses lossy imports; only errors a change introduces block a
  write (`W_PREEXISTING_ERROR` for the others); retyping a sub-process with
  content needs `--force` (`E_WOULD_DROP_CONTENT`); associations follow a
  bridged flow.
- **Incremental layout and format ops** (#4, #5, #6, #8, #9 partly, #10): a
  growing frame makes room around it instead of growing over foreign shapes
  ("frame mode" of the space tool); unconnected nodes go below their own
  container's content; `place` / `align` refuse to push a reference's frame
  away (`E_NO_ROOM`); the metrics gained `frameIntrusion`, `frameOverlap` and
  `degenerateEdge` (hard, weight 10) and a real segment test for `through`;
  no connection is written with fewer than two waypoints.
- **Full engine** (#7, #17, #18, #20, #23 partly, #24): lane bands follow the
  content after loop routing; event sub-processes go into their own lane and
  honour collapse; collaboration annotations are laid out; pools are ordered
  by message-flow cost and message-flow legs avoid shapes.
- **Found by the gate, fixed:** (a) growing a task inside an event
  sub-process that the drawing has outside its member lane moved the
  sub-process 600 px down without the task (`outsideSub`; drawings of the
  previous engine version, which put event sub-processes into the last lane;
  the pre-step-1 build does the same); (b) removing a node next to a flow
  with a stale `incoming` entry on another node (a modeler file) failed with
  `E_DANGLING_REF`; (c) a raw NUL byte in a source file, which makes git treat
  it as binary; (d) a regression of the new frame mode: `place --row-of R`
  could make the shapes around a pinned reference R room and push them onto
  it (one step in 16,000 fuzz steps). The fix is general: `place` / `align`
  never write a new overlap (the references move along when the request
  still holds, else `E_NO_ROOM`), which also fixes #11. Regression tests:
  `test/step1-gate.test.ts`, `test/repo-hygiene.test.ts`, and the two #11
  walks of `test/fuzz.test.ts` now pass.

### Open findings from the gate

- A data object or annotation that finds no free spot falls back to its
  first candidate and can land inside a foreign sub-process (reported as
  `frameIntrusion`).
- Data associations are not rerouted after `split` or `move --lane` and can
  run through gateways.
- `labelOnLine` still uses the bounding box of a segment, so a diagonal
  association counts every label in its box (#9); most `labelOnLine`
  additions in the benchmark are this artefact.
- An edit on a drawing of the previous engine version that has event
  sub-processes outside their lanes keeps that drawing (incremental mode);
  only a full redraw moves them into their lanes.

## Coverage gaps

What the audit found untested or only weakly tested before this step:

1. **Edits inside sub-processes at depth >= 2** (insert, move, split, boundary),
   including event sub-processes nested in sub-processes. Found broken (#4).
2. **Target-size real geometry**: 100+ flow nodes per plane, 300–700 KB,
   Camunda 8. Nothing local came close, and generated stand-ins are too regular.
3. **Long agent sessions**: sequences of 20–50 edits on one model. Unit tests
   are single-op; 15 % of real-model sessions ended with a defect.
4. **Incremental layout with parallel, inclusive and event-based gateways,
   transactions, ad-hoc sub-processes, call activities, intermediate and link
   events**: no unit test at the time.
5. **Artifacts on removed, moved, collapsed or other-plane elements**
   (associations, data associations). Found broken (#15, #35, #75).
6. **Files containing unsupported kinds** (complexGateway): every write blocked (#26).
7. **Format operations on nested or multi-plane drawings and on message-flow labels.**
8. **Group-heavy drawings**: groups count as overlaps, so the hard-defect
   oracle produces false positives on such files.
9. **Not covered at all**: vertical pools beyond the refusal path,
   choreographies, second diagram views beyond collapsed planes, deployment of
   the outputs to a real engine.
10. **Infrastructure**: no CI, no property-based tests, and the benchmark and
    fuzzer lived outside the repository. This step adds `tools/bench`,
    `tools/fuzz`, `test/fuzz.test.ts` and `npm run gate` (see testing.md);
    a CI job and a scheduled run on a private corpus are still to be set up.

## Recommended roadmap

**P0, correctness and the oracles**

- Make the metrics see frame intrusions, overlapping frames and degenerate
  edges (#8) and keep them hard; the bench, the fuzzer and the property test
  pick new kinds up automatically.
- Fix nested-container growth (#4, #5, #6, #11) with regression fixtures for
  nested sub-processes (depth 2–3, event sub-process inside a sub-process,
  siblings in other row bands).
- Stop treating vendor extension ids as BPMN ids (#1); move the lossy-import
  guard into the library path (#3); keep trigger-detail vendor attributes (#2).
- Run `npm run gate` in CI on every change; run the bench and a longer fuzz
  campaign on the private corpus on a schedule, outside the repository.
- Obtain two or three anonymised target-size models (ids, names and docs
  renamed, geometry kept) and add synthetic fixtures that reproduce their
  defects.

**P1, embedding and roundtrip**

- Text-preserving output (root tag, attribute order, prolog, comments, CDATA)
  and true no-op writes (#30, #31, #44–#47).
- An isomorphic core without fs / process access (#33) and op validation in
  the library entry points (#49).
- Platform detection and typed vendor adapters (#28, #29), a pluggable
  validation profile matching the host's save gate (#27, #26).
